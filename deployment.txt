deployment: oracle cloud always free
=====================================

ziel: dieses repo 1:1 per docker compose auf einer dauerhaft kostenlosen
oracle cloud vm laufen lassen. kein umbau des scripts noetig.


1. oracle cloud account
------------------------

- auf https://www.oracle.com/cloud/free/ registrieren
- kreditkarte zur verifizierung noetig, es wird aber nichts abgebucht,
  solange man im "always free"-rahmen bleibt


2. vm erstellen
----------------

- Compute -> Instances -> "Create Instance"
- shape: Ampere (ARM) VM.Standard.A1.Flex, 1 OCPU / 6 GB RAM reicht locker
  (always free deckt bis zu 4 OCPU / 24 GB insgesamt ab)
- image: Ubuntu (aktuelle LTS)
- ssh key: beim erstellen ein neues keypair generieren lassen und den
  private key lokal sichern (ssh -i <key>.pem ubuntu@<public-ip>)
- networking: default vcn/subnet reicht, keine offenen inbound ports
  noetig (das script macht nur outbound requests)


3. docker auf der vm installieren
-----------------------------------

per ssh auf die vm, dann:

    curl -fsSL https://get.docker.com | sh
    sudo usermod -aG docker $USER
    # neu einloggen, damit die gruppe greift
    exit

wieder einloggen, dann pruefen:

    docker version


4. repo auf die vm bringen
----------------------------

    git clone <repo-url> horstempfaenger
    cd horstempfaenger


5. .env anlegen
-----------------

    cp .env.example .env
    nano .env

DISCORD_WEBHOOK_URL=<echte webhook-url eintragen>

.env bleibt lokal auf der vm, wird nie committed (steht in .gitignore).


6. outlets konfigurieren
--------------------------

in config/outlets.yaml pro agentur die feed_url eintragen und
active: true setzen, sobald ein feed recherchiert ist.


7. starten
------------

    docker compose up -d --build

laeuft ab jetzt dauerhaft im hintergrund (restart: unless-stopped in der
docker-compose.yml startet den container auch nach vm-reboot automatisch
neu).


8. kontrollieren
-------------------

    docker compose logs -f

zum stoppen:

    docker compose down


9. updates einspielen
------------------------

    git pull
    docker compose up -d --build

data/state.db (dedup-datenbank) bleibt dabei erhalten, liegt als volume
ausserhalb des containers.
